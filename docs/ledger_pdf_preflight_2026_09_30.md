# 토스 거래내역서 로컬 사전 검토 (2026-09-30)

## 범위와 보존

사용자가 제공한 2026-06-01~2026-09-30 원화·달러 거래내역서 PDF(80쪽)를
로컬에서만 읽었다. 원본 PDF, 사용자 제공 주문·수수료 화면 6개, 페이지별 추출 텍스트,
행별 검토 CSV, 해시 목록은 Git 제외 `backups/ledger_pdf_*`에 보존한다.
계좌 번호와 실명, 원문 행은 저장소에 넣지 않았다. 파일들은 암호화되지 않은 민감 자료다.

`scripts/review_toss_statement.py`는 PDF 파서가 아니다. 로컬 문서 도구
`pypdf 6.10.0`의 레이아웃 추출 결과를 사용했다. 별도 로컬 도구가 생성한
페이지별 레이아웃 텍스트를 검토 표로 옮기는 표준 라이브러리 전용 도구다.
PDF 추출에 사용한 문서 도구는 AlphaPilot의 런타임 의존성에 추가하지 않았다.
출력은 새로운 `backups` 하위 폴더만 허용하고 기존 결과를 덮어쓰지 않는다.

두 화면의 날짜 차이는 확인되지만, PDF 열 제목은 `거래일자`이므로 이를
자동으로 `결제일`이라고 해석하지 않는다. 시각·시간대와 결제 기준은 별도 확인 대상이다.

## 후속 오프라인 매핑 검토표 갱신

2026-10-02 후속 오프라인 검토에서는 네 PDF의 관측 행 1,403개를
`backups/ledger_oct_boundary_20261002_84fa6a3e/overlap_all_v3`에 보존했다.
기존 세 PDF의 관측 행 1,337개에 대한 중복 판정을 유지한 채 새 PDF 66개만
기존 잠정 구분 행과 대조했다. 전체 1,403개 관측 행 중 73개는
**필드 일치 중복 후보**다. 별개 체결 가능성을 배제할 고유 ID가 없으므로
운영 중복 결정으로 사용하지 않는다. 원본 페이지에서 같은 행의 재수록으로
확인한 3개는 근거 수준을 구분해 별도 수동 결정으로 남겼다. 두 부류를
잠정 제외한 구분 행은 1,327개이며 전체 거래 수 인증이 아니다.
네 PDF를 순서대로 한 번에 비교한 중간 출력은
동일 행이 여러 보조 PDF에 반복될 때 새 관측으로 잘못 분류하므로
`overlap_all_v2/REJECTED.md`로 사용 금지를 표시하고 삭제하지 않았다.
후속 비교 도구는 문서마다 기존 관측의 다중집합 수량을 새로 대조하도록 보강했다.
네 개 이상 검토 CSV를 입력해도 앞선 문서의 일치 좌표를 소모하지 않으며,
같은 출처 좌표가 입력에서 반복되면 중단한다. 기존 `overlap_all_v2` 결과를
소급 수정하거나 운영 중복 결정으로 승격하지 않는다. 새 출력 역시 Git 제외
`backups` 아래의 새 폴더에만 생성하는 잠정 검토 자료다.

기존 2026-06-01~09-30 매핑 검토표 1,267개는 새 PDF에서 처음 관측한
9월 30일 표시 행 3개를 포함해 1,270개로 갱신했다. Git 제외
`backups/ledger_oct_boundary_20261002_84fa6a3e/mapping_inventory_v2`의
1,403개 관측 행 중 PDF `거래일자` 표시 기준 범위 밖 57개(5월 28~29일
36개, 10월 1~2일 21개), 필드 일치 중복 후보 73개, 수동 확인 재수록
3개를 별도 표시했다. 범위 안으로 잠정 분류한 1,270개는 모두
`in_period_mapping_blocked`다. `거래일자`의 원장 날짜 의미가 확인되면
이 기간 분류는 달라질 수 있다. 운영 입력용 명세서 CSV나 매핑 JSON은
생성하지 않았다. 9월 29일 주문 화면과 10월 1일 명세서 매수 9개는
같은 Git 제외 폴더의 `order_links_v1.json`에 종목명·수량 기준 고유 후보로
기록했다. 주문 ID,
날짜 기준, 금액 차이는 미확정이므로 이는 운영 원장 이벤트가 아니다.

## 남은 운영 차단 조건

- 기초·기말의 **정산 현금, 미수·미지급, 전 종목 보유 수량** 원본이 아직 없다.
- 개별 거래의 원본 수동 검토와 날짜·거래 유형 매핑 확정이 끝나지 않았다.
- 기존 운영 원장과의 중복·정정 대조, 전체 계좌 잔고 대사, 수익률 검증을 하지 않았다.
- 따라서 `coverage_verified=false`다. CSV는 검토용이며 운영 DB 입력으로 사용하지 않는다.
  가용 매수금액을 정산 현금으로 대용하지 않는다.

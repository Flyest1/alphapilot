# 토스 거래내역서 로컬 사전 검토 (2026-09-30)

## 범위와 보존

사용자가 제공한 2026-06-01~2026-09-30 원화·달러 거래내역서 PDF(80쪽)를
로컬에서만 읽었다. 원본 PDF, 사용자 제공 주문·수수료 화면 6개, 페이지별 추출 텍스트,
행별 검토 CSV, 해시 목록은 Git 제외 `backups/ledger_pdf_*`에 보존한다.
계좌 번호와 실명, 원문 행은 저장소에 넣지 않았다. 파일들은 암호화되지 않은 민감 자료다.

`scripts/review_toss_statement.py`는 PDF 파서가 아니다. 로컬 문서 도구
`pypdf 6.10.0`의 레이아웃 추출 결과를 사용했다. 별도 로컬 도구가 생성한
페이지별 레이아웃 텍스트를 검토 표로 옮기는 표준 라이브러리 전용 도구다.
PDF 추출에 사용한 문서 도구는 AlphaPilot의 런타임 의존성에 추가하지 않았다.
출력은 새로운 `backups` 하위 폴더만 허용하고 기존 결과를 덮어쓰지 않는다.

## 전사·대조 결과

| 검토 항목 | 로컬 결과 | 의미의 한계 |
|---|---:|---|
| 날짜 시작 행 | 1,258 (KRW 195, USD 1,063) | PDF의 모든 거래가 실제로 존재했다는 인증 아님 |
| 환전 원화 출금 ↔ 달러 입금 | 128 ↔ 128, 날짜·환율·원화 금액 다중집합 128쌍 일치, 미해석 0 | 환전 스프레드·실제 체결 환율 검증 아님 |
| 매매 정산식 | 938/938 일치 (KRW 34, USD 904), 미해석 0 | USD는 표시 반올림 오차 0.005달러 이내; 잔고 대사 아님 |
| 비영(非零) 비용 행 | KRW 구간: 수수료 19, 거래세 10, 제세금 20. USD 구간: 수수료 54, 제세금 61 | USD 구간의 원화 환산 비용 칸은 같은 거래의 중복 표기; 비용 총합이나 과세 적정성 아님 |
| PDF 레이아웃 붙음 | 보유잔고와 현금잔액이 붙어 나온 73행을 분리 표시 | 원본 화면 수동 대조 전에는 검증 등급 아님 |

검토 CSV의 각 행에는 PDF 해시, 1부터 시작하는 페이지·페이지 내 행 번호,
통화, 거래일자, 유형, 원문 줄, 추출 열, 검토 상태가 있다. 1,258행 모두
`needs_source_review` 또는 `layout_join_recovered`로 남겼으며 자동으로 `verified`를
부여하지 않았다. 특히 73행은 원본 PDF 화면과 대조해야 한다.
정산식 검사는 `구매`·`판매`만 대상으로 하며, 입출금·배당·이자·환전의
정산식이나 행 간 현금잔액 연속성은 검증하지 않았다.

정산식은 PDF에 표시된 매매의 거래대금 ± 수수료·거래세·제세금과 정산금액을
비교한 것이다. 주문 화면의 구매 총액과 PDF의 수수료 포함 정산금액이
대응하는 사례를 확인했다. 따라서 주문 화면의 총 구매 금액만으로 수수료 0을 추정하면 안 된다.
두 화면의 날짜 차이는 확인되지만, PDF 열 제목은 `거래일자`이므로 이를
자동으로 `결제일`이라고 해석하지 않는다. 시각·시간대와 결제 기준은 별도 확인 대상이다.

## 9월 말 경계

2026-09-29 주문 화면의 한 해외주식 매수는
`2026년 10월 1일 출금 예정`이라고 표시한다. 같은 화면에 있는 9개 주문의
종목·수량 조합은 PDF의 2026-09-29 달러 거래행에서
찾지 못했다. PDF 표시 기간은 9월 30일까지이며, 달러 거래행의 마지막 날짜는
9월 29일이다. 이 주문들을 PDF 누락 거래로 단정하거나 9월 현금 지출로 합산하지 않는다.
10월 거래내역서 또는 해당 주문의 입출금·결제 증빙이 필요하다.

## 남은 운영 차단 조건

- 기초·기말의 **정산 현금, 미수·미지급, 전 종목 보유 수량** 원본이 아직 없다.
- 개별 거래의 원본 수동 검토와 날짜·거래 유형 매핑 확정이 끝나지 않았다.
- 기존 운영 원장과의 중복·정정 대조, 전체 계좌 잔고 대사, 수익률 검증을 하지 않았다.
- 따라서 `coverage_verified=false`다. CSV는 검토용이며 운영 DB 입력으로 사용하지 않는다.
  가용 매수금액을 정산 현금으로 대용하지 않는다.

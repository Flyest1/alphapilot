# 거래내역서·잔고증명서 날짜 기준 대조 (2026-10-03)

## 결과

두 잔고증명서는 **결제기준이며 미결제 매매를 제외**한다고 명시한다.
기초·기말 기준일에 대응하는 거래내역서의 마지막 원화·달러 표시 잔액은
증명서의 같은 통화 현금과 **4건 모두 숫자 기준으로 일치**했다.
이것은 네 개 현금 관측값의 대조이며, 전체 거래 재생이나 계좌 대사 완료는 아니다.
거래내역서 `거래일자`의 체결일·결제일·계좌 반영일 구분과 시간대는 미확정이다.

원본과 기존 산출물을 보존하고 새 비공개 결과를 Git 제외
`backups/ledger_date_basis_20261003_v1`에 생성했다. 개별 금액·수량·종목명·
계좌 식별자는 이 문서에 넣지 않았다. 제품 코드·의존성·스키마 변경,
운영 DB 쓰기, 브로커 호출, 주문 실행은 하지 않았다.

## 기준일과 현금 대조

거래내역서의 **표시 날짜가 증명서 기준일 이하인 행** 중 통화별 마지막 행을
선택했다. 이 선택은 PDF 날짜에 따른 관측 비교이며 원장 event_date에 따른
기간 분류를 확정한 것이 아니다. 달러는 원화 환산액 대신 달러 표시값을 비교했다.

| 증명서 기준일 | 통화 | 사용한 거래내역서 | 마지막 표시 날짜 | 원문 위치 | 현금 일치 |
|---|---|---|---|---|---|
| 2026-05-31 | KRW | 5월 경계 5쪽 PDF | 2026-05-29 | 2쪽, 날짜 시작 행 3 | 일치 |
| 2026-05-31 | USD | 5월 경계 5쪽 PDF | 2026-05-29 | 4쪽, 날짜 시작 행 3 | 일치 |
| 2026-09-30 | KRW | 10월 2일 발급 6쪽 PDF | 2026-09-30 | 1쪽, 날짜 시작 행 2 | 일치 |
| 2026-09-30 | USD | 10월 2일 발급 6쪽 PDF | 2026-09-30 | 4쪽, 날짜 시작 행 9 | 일치 |

각 원문 해시·행 좌표·표시 금액·차액은 비공개
`comparison/cash_boundary_comparison.csv`에 있다. 기존 레이아웃 추출과 별도로
pdfplumber의 원문 셀을 읽어 네 값의 일치를 재검사하고, 해당 행을 렌더링해 확인했다.
원화 두 행은 기존 검토표의 `layout_join_recovered`, 달러 두 행은
`needs_source_review`를 유지한다. 현금 셀 확인이 행 전체를 확정 등급으로 바꾸지는 않는다.

기말에는 자료 버전 선택이 중요하다. 최초 80쪽 PDF의 통화별 마지막 표시 잔액은
두 통화 모두 9월 30일 증명서와 불일치한다(달러 마지막 표시 날짜는 9월 29일).
9월 경계 3쪽 PDF도 두 통화 모두 불일치한다. 이후 발급된 6쪽 PDF의
9월 30일까지 마지막 표시 잔액에서 두 통화가 일치한다. 기존의 추가 9월 30일
행 관측과 함께, 먼저 발급된 자료의 마지막 잔액을 최종 기말 현금으로 쓰면
안 된다는 근거다. 불일치만으로 거래 누락 원인이나 문서 오류를 확정하지 않는다.

## 구매·출금 예정일·PDF 표시 날짜

보존된 9월 29일 주문 화면을 다시 확인했다. 선택된 구매의 `구매 시간`은
**2026-09-29 22:52**, 안내는 **2026년 10월 1일 출금 예정**으로 표시한다.
시간대나 공식 결제 완료 시각은 화면에 명시되지 않았다. 출금 예정은 완료 증거가 아니다.

화면에 보이는 아홉 수량을 6쪽 PDF의 **2026-10-01 달러 구매 9행**과
Decimal로 다시 대조했다. 각 수량의 후보가 그날 구매 행 중 하나씩 존재했다.
이번 재검사는 수량 기준 후보 연결이며 주문 고유 ID·체결 동일성을 확정하지 않는다.
기존 종목명·수량 연결 검토와 금액 정의 차이는
[원문 경계 검토](ledger_pdf_preflight_2026_09_30.md)의 해당 절을 함께 따른다.

따라서 구매 화면 날짜, 출금 예정일, PDF 표시 날짜를 한 날짜로 합치면 안 된다.
이 사례는 일부 구매의 PDF 표시가 이후 현금 반영 날짜와 연결될 가능성을 뒷받침하지만,
모든 거래 유형의 `거래일자`가 결제일이라는 공식 정의는 아니다.
9월 29일 구매 후보를 PDF의 10월 1일 표시만 보고 경제적 기간 밖으로 제외하거나,
9월 30일 증명서에 없는 수량·미결제 대금을 0으로 채우지 않는다.

## 확정 범위와 남은 연결

| 항목 | 현재 판단 |
|---|---|
| 증명서 기준일 | 기초 5월 31일, 기말 9월 30일 확인 |
| 증명서의 결제기준·미결제 제외 | 두 원문의 명시적 설명 확인 |
| 기준일 현금 관측값 | KRW/USD, 기초/기말 4개 일치 |
| 거래내역서 날짜 열 | `거래일자` 확인, 경제적 의미 미확정 |
| 시간대·일자 마감 시각 | 미확정 |
| 미결제 포지션·미수·미지급 | 증명서로 완전성을 확정할 수 없음 |
| 전체 거래 완전성·티커 대응·원장 재생 | 미검증 |

거래내역서 네 문서 94쪽을 새로 추출한 텍스트에서 `체결일`, `결제일`,
`시간대`, `미결제` 설명을 찾지 못했다. 이는 제공된 문서의 추출 결과이며,
증권사의 다른 문서에도 정의가 없다는 주장은 아니다.

현재 원장 재생은 체결 수량을 결제 전 포지션에 반영하고 미결제 매매 대금을
receivables/payables로 분리한다. 따라서 결제기준 증명서에 미결제 연결 근거를
추가해야 완전한 기초·기말 LedgerBalance를 만들 수 있다. 문서에 표시된
브로커 미수금 0은 그 연결을 대신하지 않는다.

다음 확인은 자료를 다시 발급받는 것보다 아래 의미와 경계 내역을 확보하는 것이다.

1. 거래 유형별 `거래일자`가 체결일·결제일·계좌 반영일 중 무엇인지,
   적용 시간대·일자 마감 기준과 미결제 거래의 수록 방식.
2. 5월 31일과 9월 30일 기준 미결제 매매의 체결 일시·결제일·수량·대금과
   이를 증명서 잔고에서 경제적 원장 잔고로 연결하는 근거.
3. 주문 고유 ID와 명세서 행 연결, 현금 반영 완료 내역. 예정 안내만으로 완료 처리하지 않는다.

## 검증과 상태

원본 해시, 네 문서의 통화별 표시 날짜 순서, 네 현금 값의 두 추출 도구 일치,
증명서 원문 정책·현금 연결과 미확정 플래그를 새로 검사했다.
`verification_v2/report.json`이 최종 검증 결과다. 첫 검증은 오른쪽 현금 셀의
가로 좌표 조건이 좁아 값을 찾지 못했으며, 기존 실패 폴더는 보존하고
단어 분리 간격·셀 좌표를 수정한 새 출력에서 검증했다.
별도 `supplemental/report.json`에는 자료 버전별 기말 잔액 일치 여부와 수량 후보 수가 있다.

기존 준비 서비스·CLI 회귀 테스트 26개가 이번에도 통과했다.
문서 전용 변경이므로 전체 백엔드·프론트엔드 검사나 운영 배포를 새로 실행하지 않았다.
`coverage_verified=false`, `stored=false`, `account_balance_reconciled=false`,
수익률 미검증 상태를 유지한다.

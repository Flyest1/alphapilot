# 수익성 개선 실행 기록

사용자가 전체 계획의 계속 진행, 가역적 결정 위임, 작업별 커밋을 승인했다.
비가역적 결과가 발생하는 작업은 실행 전에 승인받는다.

## 판단과 작업 순서

- 판단: 운영 전략을 바꾸기 전에 측정 체계를 복구한다. 잘못된 수익률로 전략을 선택하는
  위험을 줄이기 위함이며, 단기적으로 신규 신호 개발이 뒤로 밀린다.
- 판단: 기존 브랜치 `codex/profitability-measurement-foundation`에서 이어간다.
  작업별 소유 파일을 나누고 검증 후 해당 파일만 커밋한다.
- 판단: 기존 원본 성과는 덮어쓰지 않는다. 교정 결과는 읽기 전용 비교 산출물부터 만든다.
- 판단: 실제 입출금 원장이 없는 평가액 변화는 실제 계좌 수익률로 표시하지 않는다.
- 판단: 운영 승격에는 실제 미래 표본이 필요하다. 12주 검증을 로컬 시뮬레이션으로 대체하거나
  검증 기간이 지나지 않았는데 완료로 보고하지 않는다.

## 작업 목록

1. 완료: 추천 만기 판정 및 행별 실패 격리 (`256dcec`).
2. 진행: 백필 페이지네이션, 오래된 표본과 가격 이력 복원 범위.
3. 진행: 평가가격 출처·결측과 포트폴리오 표시·스냅샷 품질.
4. 진행: 비교 지표의 의미 교정, 원장 없는 수익률 오표시 제거.
5. 진행: 한미 시장 시간축과 실제 보유 비중 기반 위험 추정.
6. 대기: 최초 판단을 보존한 비파괴 재평가와 결측 원인 분류.
7. 대기: 사전 등록된 최소 challenger와 시간순 검증·비용 스트레스.
8. 대기: 확률 및 포트폴리오 통합, 불변 모델 계보·미래 shadow 관찰 준비.
9. 대기: Toss 공식 계약 기반 격리된 실행 모의검증·복구 설계.
10. 실운용 전 승인 필요: 실제 주문과 자금 사용. 미래 표본 검증은 실제 시간이 필요하다.

전체 계획 원본: [분석 및 계획](profitability_research_plan_2026_09_10.md).

## 2026-09-11 검증 중인 결정

- 판단: 전체 포트폴리오 시세가 불완전하면 평가액·수익률을 `null`로 확장한다.
  숫자 0으로 오해시키는 것을 막는다. 기존 숫자 응답은 호환되며 소비 화면을 함께 수정한다.
- 판단: 새 사이클의 `metadata.original_decision`에 최초 기준과 식별자를 저장한다.
  기존 사이클에 최신 조건을 최초 조건인 것처럼 채우지 않는다. 기존 JSONB를 사용한다.
- 판단: 과거 재평가는 로컬 JSON 입력과 별도 결과 파일로 수행한다. 입력 해시를 기록하고
  기존 결과 파일 덮어쓰기도 거부한다. 종가만 있거나 날짜가 중복된 장벽 평가는 제외한다.
- 판단: 한미 상관은 양쪽 시장의 해당 세션이 끝난 다음 UTC 날짜부터 비교한다.
  실제 현재 보유 비중을 사용하되 환율·과거 보유 변경을 반영한 실제 운용 성과라고 부르지 않는다.
- 한계: 거래소별 달력 없이 내부 누락 세션의 완전성을 보증할 수 없다. 재평가를 잠정 연구로
  표시하고 운영 승격에 직접 사용하지 않는다. 백필은 전체 작업 목록을 메모리에 먼저 모으므로
  외부 동시 작성자에 대한 DB 스냅샷 격리는 제공하지 않는다.

## 로컬 비파괴 재평가 실행

입력 JSON은 `cycles` 배열과 `histories` 객체를 가진다. histories의 키는 티커이고 값은
`date`, `close`, `high`, `low`가 있는 일봉 배열이다. `price_provenance`에 공급자·조정 기준·
수집 시각을 기록한다. 새 사이클의 최초 조건이 없는 기존 자료는 제외 사유로 집계된다.

```powershell
python scripts/audit_recommendations.py input.json --as-of 2026-09-10 --output audit.json
```

이 명령은 DB나 외부 서비스에 연결하지 않고, 입력 원본과 기존 결과 파일을 바꾸지 않는다.

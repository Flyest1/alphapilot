# AI 자문 기능 구현 계획 (2026-07)

## 목표

AlphaPilot에 수동 요청 중심의 `AI 자문` 탭을 추가한다. 계산 가능한 수치는 백엔드에서
결정론적으로 계산하고, OpenAI는 수집된 근거와 계산 결과 안에서만 설명을 생성한다.

자동매매, 주문 수량, 주문 미리보기, 브로커 실행 기능은 포함하지 않는다. 모든 결과는 투자
의사결정 지원 정보이며 수익을 보장하지 않는다.

## 공통 계약

- 사용자 토큰으로 보호되는 수동 요청만 허용한다.
- 요청은 비동기 작업으로 접수하고 `queued`, `running`, `completed`, `failed` 상태를 저장한다.
- 동일한 활성 요청은 요청 해시로 중복 실행을 방지한다.
- 결과에는 데이터 기준시각, 제공자, 신선도, 누락 필드, 한계, 근거 목록을 저장한다.
- 상태 API는 마이그레이션 적용 여부와 OpenAI 설명 설정 여부를 구분한다.
- OpenAI 설명은 `available`, `not_configured`, `no_evidence`, `generation_failed`를 구분한다.
- 데이터가 없으면 `insufficient_data` 또는 데이터 제한 상태를 표시하고 값을 만들지 않는다.
- 기존 `ReportContent`와 `/api/reports` 계약은 변경하지 않는다.
- 사용자 화면의 위험 등급은 `상대적 위험 낮음`, `주의`, `고위험`을 사용한다.

## 1. 저평가 미국 주식 발굴

입력:

- 선택적 미국 주식 티커 목록
- 목록이 없으면 현재 글로벌 후보 유니버스
- 결과 개수, 기본 5개

필수 결과:

1. 최근 3개월 주가 흐름
2. 최근 분기 매출 성장률
3. 영업이익률 변화
4. 잉여현금흐름 변화
5. 부채비율과 현금 보유 상황
6. 다음 분기 또는 연간 회사 공식 가이던스
7. 현재 밸류에이션의 과거 평균 대비 수준
8. 시장이 우려하는 핵심 리스크
9. 6~18개월 관점 상위 5개
10. 종목별 투자 매력도 10점 평가

입력:

필수 결과:

1. 최신 10-K, 10-Q, 8-K와 accession number
2. 새롭게 추가·강조된 위험
3. 매출 성장·수익성 악화 가능성
4. 부채·현금흐름·유동성 위험
5. 규제·소송 위험
6. 고객 집중도와 공급망 위험
7. 경영진의 조심스러운 부정적 표현

9. `상대적 위험 낮음`, `주의`, `고위험` 평가와 근거

최신 10-K, 10-Q, 8-K 중 하나라도 없거나 본문을 확보하지 못하면 등급을 만들지 않고

SEC EDGAR는 현재 허용 서비스 목록에 없으므로 사용자 승인과 `AGENTS.md` 변경 전에는 실제
네트워크 호출을 추가하지 않는다.

구조화 제공자가 없으면 `data-limited`로 표시한다.

## 완료 기준

각 기능은 다음을 모두 만족해야 완료다.

1. 수동 요청과 비동기 상태 조회가 동작한다.
2. 결과가 Supabase에 영속 저장된다.
3. 각 필수 항목이 값 또는 명시적인 데이터 부족 상태로 제공된다.
4. 근거 없는 숫자·공시 문장·가격을 생성하지 않는다.
5. AI 설명의 사실·계산 문장은 저장된 `evidence_id`를 인용하고 근거에 없는 수치를 거부한다.
6. 백엔드 단위·API 테스트와 프론트엔드 폼·polling·렌더링 테스트가 통과한다.
7. 운영 마이그레이션 적용과 배포 후 인증된 화면 검증을 완료한다.

## 9. 승인 상태와 운영 전제 (2026-07 갱신)

SEC EDGAR와 FRED는 사용자 승인된 읽기 전용 데이터 소스다. 현재 AI 자문 기능에 대한 코드 연결 작업이 진행 중이며, 데이터 소스·마이그레이션·OpenAI 설명 설정의 가용 상태를 각각 구분해 표시한다. 외부 서비스 추가, 브라우저 자동화·HTML 스크래핑, 주문·자동매매 기능은 이 계획의 범위에 포함하지 않는다.

### SEC EDGAR

- `data.sec.gov`, 승인된 `www.sec.gov` 티커 매핑 파일, 공식 `www.sec.gov/Archives` 공시 산출물만 사용한다.
- submissions/companyfacts JSON, 구조화된 filing XML, complete-submission SGML/text, N-PORT 자료를 읽기 전용으로 정규화한다. 누락·손상된 자료는 실패 처리하며 사실이나 수치를 보완해 만들지 않는다.
- 모든 요청은 실제 연락 가능한 이메일을 포함한 `SEC_EDGAR_USER_AGENT`를 서버 환경 변수로 선언하고, 애플리케이션 전체 초당 5회 이하, 제한된 재시도·백오프, immutable accession 문서 캐시를 준수한다.
- N-PORT 보유·흐름 결과는 공시 기준 기간과 공시 지연을 함께 노출한다. 현재 또는 일별 ETF 흐름으로 표현하지 않는다.

### FRED 및 yfinance 한계

- FRED는 허용 목록의 거시 시계열을 HTTPS JSON으로 읽기 전용 조회한다. 관측값에는 series id, 단위, 관측일, 조회 시각 및 가능하면 revision/vintage 정보를 보존한다.
- FRED 데이터는 과거 증거일 뿐 미래 전망이나 투자 수익을 보장하지 않는다. FRED 기반 사용자 결과에는 다음 문구를 표시한다: “This product uses the FRED® API but is not endorsed or certified by the Federal Reserve Bank of St. Louis.”
- yfinance 가격·거래량, ETF 메타데이터 및 관련 계산은 제공 범위와 갱신 주기에 제한된 프록시다. 실시간 ETF 흐름, 완전한 ETF 구성, 확정적 가격·거래량 또는 분석가 컨센서스를 대체하지 않으며, 근거가 부족하면 `data-limited` 또는 `insufficient_data`를 반환한다.

### Oracle 운영 절차

운영 담당자는 Oracle VM의 `/etc/alphapilot/backend.env`에 `FRED_API_KEY`와 실제 연락 이메일을 포함한 `SEC_EDGAR_USER_AGENT`를 직접 설정한 뒤 아래 명령으로 재시작한다.

```bash
sudo nano /etc/alphapilot/backend.env
sudo chmod 600 /etc/alphapilot/backend.env
sudo systemctl restart alphapilot-backend
sudo systemctl status alphapilot-backend --no-pager
curl http://127.0.0.1:8000/health
```

실제 API 키와 이메일은 채팅, 저장소, 커밋, 이슈, 프론트엔드, GitHub Pages, Supabase, 로그에 기록하거나 노출하지 않는다. 운영 환경 파일에만 저장한다.

# 운영 원장 적용 준비

## 이번 범위

명세서가 아직 없는 상태에서도 자료 수집 항목과 검증 절차를 준비한다.
`prepare_account_ledger.py`는 로컬 파일만 읽고 새 보고서 폴더에 결과를 쓴다.
DB 접속·환경 키 로딩·토스 API 호출·운영 저장·실제 수익률 계산은 하지 않는다.
기존 정규화, 중복 검토, 원장 재생, 잔고 대사 엔진을 재사용한다.

`ready_for_review`는 제공된 자료의 자동 사전 점검을 통과했다는 뜻이다.
실제 명세서 내용의 진실성, 계좌 전체 기간의 완전성, 기존 운영 원장과의 일치 또는
운영 저장 승인을 뜻하지 않는다. `coverage_verified=false`, 수익률·실현손익=null을 유지한다.

## 필요한 자료

| 자료 | 확인할 내용 |
|---|---|
| 거래 명세서 | 같은 계좌·기간의 매매, 입출금, 배당, 이자, 환전, 수수료, 세금 |
| 정정·특수 거래 | 취소·정정, 주식 입출고, 기업행사, 미결제 거래 |
| 기초 잔고 원본 | 시작일 전날 기준의 통화별 정산 현금, 미수·미지급, 보유 수량 |
| 기말 잔고 원본 | 종료일 기준의 같은 항목, 같은 계좌·정산 기준 |
| 명시적 매핑 | 실제 열 제목, 날짜·시간대, 거래 유형, 금액 부호, 비용 및 결제 표현 |

**토스 가용 매수금액은 정산 현금 자료로 사용하지 않는다.** 모르는 금액·비용을 0으로
채우지 않는다. CSV만 거래 행으로 해석한다. 잔고 근거가 PDF/XLSX여도 파일 해시 연결만
확인하며 내용은 추출하지 않는다. 실제 토스 서식 지원을 검증한 상태는 아니다.

## 사용 순서

1. 비공개 자료 폴더를 새로 만든다.

```powershell
backend/.venv/Scripts/python.exe scripts/prepare_account_ledger.py init `
  --output-dir backups/ledger_preparation_20260923
```

`manifest.json`, `opening.json`, `closing.json`, `mapping.json`, `README.md`가 생성된다.
계좌·날짜·잔고는 비어 있고 확인 항목은 모두 false다. 원본을 이 폴더 안에 복사해 보관한다.
계좌 식별자는 실제 계좌 번호 대신 일관된 별칭을 권장한다.

2. manifest의 계좌·시작일·종료일·확인 시각을 입력한다.

기간은 한국시간 계좌 기준일이다. `observed_at`은 종료일이 지난 뒤의 시간대 포함 시각이다.
미국 날짜만 있는 거래를 한국 날짜로 추측하지 않는다. 정확한 시각이나 별도 검증된
기준일이 없으면 날짜 모호성으로 차단될 수 있다.
가상 자료면 `synthetic=true`를 명시한다. 이 값은 사용자 선언이며 실제 여부를 인증하지 않는다.

아래는 manifest의 경로 지정 구조다. 날짜는 확보한 자료의 실제 기간으로 입력한다.

```json
{
  "opening": {"balance": "opening.json", "evidence": "opening-original.pdf"},
  "closing": {"balance": "closing.json", "evidence": "closing-original.pdf"},
  "statements": [
    {
      "csv": "statement.csv",
      "mapping": "mapping.json",
      "period_start": "YYYY-MM-DD",
      "period_end": "YYYY-MM-DD"
    }
  ]
}
```

이는 전체 manifest가 아닌 해당 필드의 예시다. 템플릿의 다른 필드를 삭제하지 않는다.
모든 입력 경로는 manifest 폴더 안의 상대 경로여야 한다. 폴더 밖 경로·링크 이탈은 거절한다.

3. 잔고 JSON을 원본과 대조해 입력한다.

`source_record_hash`는 해당 잔고 **원본 파일 전체**의 SHA-256이다.

```powershell
(Get-FileHash backups/ledger_preparation_20260923/opening-original.pdf -Algorithm SHA256).Hash.ToLowerInvariant()
```

`cash`, `receivables`, `payables`에 KRW와 USD를 모두 명시한다.
금액·수량은 `"10.25"`처럼 소수 문자열을 사용한다. 천 단위 쉼표·지수·float는 허용하지 않는다.
`positions` 키는 `KR:005930:KRW`, `US:AAPL:USD` 형식이다. 보유가 없다고 확인한 경우만 `{}`를 쓴다.
원본 해시 일치는 파일 연결만 검증한다. 사람이 옮겨 적은 숫자가 원문과 같은지는 별도로 확인한다.

4. 실제 CSV를 보고 mapping.json을 작성한다.

공통 어댑터 규칙은 [명세서 연결 문서](account_ledger_storage_2026_09_11.md)를 따른다.
열 이름·유형·환율·수수료·세금·결제일을 자동 추정하지 않는다. 매핑의 초기 quality는
provisional이다. 원문을 검토한 행에만 명시적으로 verified를 선언한다. 도구는 등급을 올리지 않는다.
명세서 기간은 거래 발생일의 최솟값/최댓값이 아닌 문서에 표시된 수록 기간을 사용한다.
선언 기간의 연결만 검사하며 실제 문서가 모든 거래를 담았는지는 인증하지 않는다.

5. manifest의 여섯 checks를 실제 자료와 대조한다.

계좌·기간, 외부 현금흐름, 비용·세금, 환전·기업행사, 결제·정정, 중복·누락을 각각 확인한다.
해당 유형의 거래가 없다는 것도 근거를 보고 확인한 경우만 true로 기록한다.
체크를 모두 true로 바꿔도 파싱 오류·대사 차이·중복 의심·재생 오류를 우회하지 못한다.

6. 새 출력 폴더로 점검한다.

```powershell
backend/.venv/Scripts/python.exe scripts/prepare_account_ledger.py check `
  backups/ledger_preparation_20260923/manifest.json `
  --output-dir backups/ledger_preparation_check_20260923
```

`report.md`는 한국어 보완 항목, 오류 행 번호, 중복 의심 개수, 통화/종목별 잔고 차이를 표시한다.
차이는 **제공된 기말 잔고 − 계산 잔고**, 허용 오차는 0이다. 일부 행이 제외됐다면 부분 자료의
대사이며 숫자가 같아도 전체 준비 완료로 처리하지 않는다. `report.json`에는 입력별 해시를 남긴다.
콘솔에는 상태·차단 개수만 표시하고 원문 메모·계좌·파일 경로·예외 내용을 출력하지 않는다.

종료 코드: 0=생성 성공 또는 검토 가능, 2=보고서 생성 완료·자료 보완 필요, 1=입출력 실패.
기존 폴더는 덮어쓰지 않는다. 복사/쓰기 실패 시 부분 생성 폴더를 보존하고 다른 폴더로 재시도한다.
보고서 출력은 Git 제외 `backups` 아래만 가능하다. 원본과 보고서는 암호화되지 않은 개인 자료다.
이 준비 폴더는 기존 원장 원본 보관소 전용 ZIP 도구의 파일 규약과 다르므로 그 도구의 백업
대상으로 지정하지 않는다. 기존 import의 원본 보존·백업 절차는 그대로 유지한다.

## 제한과 후속 단계

- 명세서 최대 24개, 입력 파일 각각 5 MiB, CSV 데이터 행 합계 최대 10,000개다.
- 거래 행이 없는 명세서는 자동 통과하지 않는다. 무거래 기간 인증은 후속 범위다.
- 문서 간 중복 의심 거래를 자동 삭제하거나 새 검토 결정을 만들지 않는다.
- 기존 운영 DB의 수집/검토 이력을 읽지 않는다. 운영 저장 전에 기존 원장과 대조해야 한다.
- 입력이나 매핑이 변경되면 새로 점검한다. 이 보고서를 저장 권한 토큰처럼 사용하지 않는다.
- 실제 파일을 확보하면 실제 서식 매핑 → 로컬 대사 → 원문 검토 → 명시적 운영 저장 순서로 진행한다.
  실제 자료가 없으므로 이번 구현 자체는 실제 계좌 대사나 수익률 검증이 아니다.

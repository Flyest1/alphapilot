# 원장 오류 복구·완전성 관리 실행 계획

사용자 요청: 묶음 1 구현 후 푸시·배포. 실제 명세서가 없으므로 가상 자료로 검증한다.

- [x] 실패/부분 수집을 동일 원문에 대한 검증된 대체 수집으로 해결하는 append-only 검토 이력.
- [x] 문서 간 동일 거래 후보 검출, 중복/별개/재검토 결정과 재생 반영.
- [x] 원본·매핑·정규화 파일의 해시 검증 백업 및 새 경로 복원.
- [ ] 실제 PostgreSQL 회귀, 전체 테스트, 독립 검토, 작업별 커밋.
- [ ] PR·CI·병합, 운영 migration 026/027, Oracle 배포와 운영 읽기 검증.

Ruling: 기존 수집·이벤트를 삭제하거나 수정하지 않는다. 검토 결정은 revision으로
추가하고 known_at 이후 결정은 과거 재생에 반영하지 않는다 — 감사와 재현 보존.

Ruling: 같은 원문·행 수의 검증 완료 수집만 오류 해결 근거로 허용한다. 실제 원문이
바뀐 교정 자료는 자동 대체하지 않는다 — 잘못된 누락 해소를 막으며 다른 문서로 수정한
거래는 별도 revision과 검토가 필요하다.

Ruling: 다른 문서의 금융 필드가 일치하면 중복 후보로 표시하지만 자동 제외하지 않는다.
검토자가 duplicate/distinct를 기록하며 reopen도 가능하다. 중복 연결과 별개 결정이
모순되면 제외를 취소하고 불완전으로 둔다 — 같은 금액의 별개 거래를 보존한다.

Ruling: 로컬 백업은 기존 승인된 파일 저장 방식과 표준 라이브러리 ZIP만 사용한다.
검증 후 새 디렉터리에만 복원하고 기존 원본을 덮어쓰지 않는다 — 암호화나 외부 백업
서비스는 추가하지 않으며 사용자는 백업 파일의 접근 권한을 유지해야 한다.

Ruling: 운영 DB에는 원장 기반 migration 026도 아직 없다. 이번 배포에 필요한 026/027을
함께 적용하되 기존 보유·보고서 테이블은 변경하지 않는다. 실주문 경로는 추가하지 않는다.

Ruling: 검토 RPC는 현재 최대 revision뿐 아니라 지정한 기존 revision을 받는다.
대체 수집·과거 기준시점에서 선택된 개정도 검토할 수 있어야 하기 때문이다.
재생에서는 선택된 개정과 검토 개정이 일치할 때만 적용해 새 정정을 숨기지 않는다.

검증: 전체 752 passed / 1 Windows symlink privilege skip, Ruff·Black 통과.
실제 PG 8개 통합 테스트 및 새 DB에서 026/027 + SQL checks 통과.

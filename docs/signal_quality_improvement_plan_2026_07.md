# AlphaPilot 분석 신뢰도 및 수익성 개선 계획

작성일: 2026-07-11
대상 단계: Post-MVP 신호 품질 고도화
관련 문서: `AGENTS.md`, `docs/development_plan_v2.md`, `docs/code_review_2026_06.md`

## 1. 문서 목적

이 문서는 현재 AlphaPilot의 기술분석, 추천 성과 추적, 백테스트, OpenAI 리포트,
GDELT 뉴스 파이프라인을 코드와 실제 운영 상태를 기준으로 재검토한 결과와 개선 순서를
정리한다.

목표는 지표 수를 무작정 늘리는 것이 아니라 다음을 달성하는 것이다.

- 추천 결과가 올바른 기준으로 측정되도록 한다.
- 운영 전략과 백테스트가 같은 규칙을 사용하도록 한다.
- 비용과 위험을 반영한 순수익 기대값을 평가한다.
- 서로 중복되지 않는 신호만 검증을 거쳐 추가한다.
- AI가 사실을 변경하지 않고 설명과 반론 검토에 집중하도록 한다.
- 뉴스의 수집 여부와 사용 근거를 감사할 수 있도록 한다.

이 계획은 투자 의사결정 지원 기능만 다룬다. 주문, 자동매매, 주문 미리보기,
자동 리밸런싱은 구현하지 않는다. 어떤 개선도 수익 또는 성공률을 보장하지 않는다.

## 2. 현재 상태 요약

### 2.1 기술분석

현재 일봉 OHLCV를 바탕으로 다음 지표를 계산한다.

- SMA 5/20/60/120
- EMA 12/26
- RSI 14
- MACD 12/26/9
- 볼린저밴드 20일, 2 표준편차
- 5일 대비 20일 평균 거래량 변화율
- 20일 고가/저가와 현재 가격 위치
- ATR 14

기술점수는 100점 만점이며 추세 30점, 모멘텀 25점, 거래량 15점,
변동성 15점, 가격 위치 15점으로 구성된다. `AGENTS.md`에 명시된 필수 지표는
구현되어 있으나, 전체 기술분석 방법을 포괄하는 시스템은 아니다.

### 2.2 현재 확인된 핵심 문제

| 우선순위 | 문제 | 영향 |
|---|---|---|
| P0 | SELL/REDUCE 추천의 목표·손절 및 승패 판정 방향이 매수 관점으로 처리됨 | 추천 승률과 성과 통계 왜곡 |
| P0 | 운영 전략과 백테스트의 BUY 점수 기준이 다름 | 백테스트 결과가 실제 운영 전략을 검증하지 못함 |
| P0 | 보정 통계가 원시 기술점수가 아니라 최종 confidence 구간을 사용함 | 순환적인 신뢰도 보정 가능성 |
| P0 | GDELT 요청이 Oracle VM에서 TLS 타임아웃 | 현재 뉴스가 AI 리포트에 전달되지 않음 |
| P0 | AI가 액션·신뢰도·가격·목표가·손절가를 다시 작성할 수 있음 | 정량 사실과 결정론적 전략이 변형될 수 있음 |
| P1 | 백테스트에 세금·수수료·슬리피지·벤치마크·국면 검증이 없음 | 실전 순수익과 위험을 과대평가할 수 있음 |
| P1 | 현재 후보 종목으로 과거를 검사함 | 생존편향 및 선택편향 발생 가능 |
| P1 | 자동 글로벌 후보군이 소수 ETF 중심 | 미국 개별주 기회 탐색 범위가 제한됨 |
| P1 | 시장 공통 뉴스 쿼리 6개가 한도를 모두 사용함 | 종목별 뉴스 검색이 실행되지 않음 |
| P2 | 데이터가 20일만 있어도 정상 분석으로 간주될 수 있음 | SMA120 등 장기 지표가 없는 상태에서 품질 오판 |

현재 누적 추천 통계는 위 문제를 수정하고 재산출하기 전까지 전략의 실제 성공률로
사용하지 않는다.

## 3. 개선 원칙

1. **측정 정확성이 신호 추가보다 우선이다.** 잘못된 성과 라벨로 학습하거나 보정하지 않는다.
2. **운영 코드와 검증 코드는 동일한 전략 함수를 사용한다.** 점수 경계와 투자성향을 중복 구현하지 않는다.
3. **모든 성과는 비용 차감 후로 평가한다.** 수수료, 세금, 환전비, 슬리피지를 포함한다.
4. **시간 순서를 지킨다.** 미래 데이터가 과거 의사결정에 유입되지 않게 한다.
5. **추가 신호는 외부 구간의 증분 가치로 채택한다.** 지표 개수나 과거 최고 수익률로 채택하지 않는다.
6. **AI와 정량 엔진의 책임을 분리한다.** 계산된 사실은 백엔드가 소유하고 AI는 설명과 비판을 담당한다.
7. **종목 수익보다 포트폴리오 위험을 함께 최적화한다.** 상관관계, 집중도, 유동성, 낙폭을 통제한다.

## 4. 단계별 실행 계획

### Phase 0. 측정 무결성 복구

목표: 현재 추천 성과와 백테스트를 신뢰할 수 있는 상태로 만든다.

#### 0-1. 추천 생애주기 방향성 수정

- BUY/HOLD/WATCH와 SELL/REDUCE를 방향별로 구분한다.
- 각 방향에 대해 favorable barrier와 adverse barrier를 명시한다.
- `hit_target`을 모든 액션의 승리로 간주하지 않는다.
- 실제 가격 이력에서 최초 장벽 도달 날짜를 `barrier_hit_at`으로 기록한다.
- 같은 날 목표와 손절을 모두 통과한 경우 보수적 판정 또는 `ambiguous` 상태를 사용한다.
- 기존 추천 사이클은 수정된 규칙으로 재계산한다.

#### 0-2. 원시 점수와 최종 신뢰도 분리

- 추천 사이클에 `technical_score`, `base_confidence`, `calibrated_confidence`를 구분해 저장한다.
- 성과 구간은 원시 기술점수 기준으로 집계한다.
- 보정 표본은 액션, 투자기간, 시장, 점수 구간, 시장 국면으로 나눈다.
- 표본 30건 미만 구간은 보정하지 않고 `uncalibrated`로 표시한다.

#### 0-3. 운영·백테스트 규칙 단일화

- 액션 매핑을 `StrategyService`의 단일 함수로 추출한다.
- 백테스트도 동일한 투자성향과 투자기간 설정을 사용한다.
- ATR 목표가·손절가와 추천 만료 규칙을 백테스트에 적용한다.
- 결과에 사용한 전략 버전과 설정 스냅샷을 저장한다.

#### 0-4. 데이터 기반 정비

- Supabase에 migration 008 `market_data_cache` 적용 여부를 확인한다.
- SMA120이 필요한 분석은 최소 120 거래일 이상을 요구한다.
- 지표별 데이터 충족 여부와 누락 사유를 별도로 기록한다.
- 분석 시점 이후에 알려진 데이터가 입력되지 않는지 점검한다.

완료 기준:

- 방향별 단위 테스트와 장벽 도달 테스트가 통과한다.
- 운영과 백테스트가 동일 입력에서 동일 액션을 생성한다.
- 기존 추천 통계가 재산출되고 이전 통계와 차이가 문서화된다.
- 데이터 부족 종목이 정상 데이터로 표시되지 않는다.

### Phase 1. 검증 가능한 백테스트 구축

구현 상태(2026-07-11): **코드·UI·회귀 검증 완료**

- 운영과 동일한 투자성향·호라이즌·ATR 장벽 규칙을 사용한다.
- 중첩 평가를 줄이는 샘플 간격과 purge/embargo 워크포워드 fold를 제공한다.
- 수수료, 국내 거래세, 환전 스프레드, 거래대금 기반 슬리피지를 추정 반영한다.
- 비용 전후 성과, 위험조정 지표, 꼬리위험, turnover, 추천 빈도를 계산한다.
- 단순 보유, SMA 추세, 단순 모멘텀 기준선과 시장 국면별 결과를 제공한다.
- 현재 후보군 기반 검증에는 생존편향 경고를 항상 표시한다.
- 전체 성과는 겹치지 않는 label 코호트를 날짜별 동일가중으로 집계하며 실제 포트폴리오
  수익률이 아닌 방향 정규화 신호 바스켓임을 명시한다.
- 연구 단계 통과 최소 기준은 겹치지 않는 평가 코호트 30개 이상, 워크포워드 fold 3개 이상,
  시장별 표본 20개 이상, 비용 차감 기대값 양수, 단순 보유 대비 최대낙폭 비악화로 둔다.
  이 기준은 자동 승격 조건이 아니며 Phase 6 challenger 검증 전 운영 규칙을 변경하지 않는다.

목표: 과거 적합도가 아니라 미래 적용 가능성과 비용 차감 기대값을 측정한다.

#### 1-1. 워크포워드 검증

- 학습·규칙 결정 구간과 평가 구간을 시간 순서로 분리한다.
- 중첩된 5일/20일/60일 수익 구간에는 purge/embargo를 적용한다.
- KR, US, ETF를 분리 평가한다.
- 상승장, 하락장, 횡보장, 고변동성 국면별 결과를 제공한다.

#### 1-2. 비용과 기준선

- 설정의 매매 수수료, 국내 거래세, 환전 스프레드를 반영한다.
- 거래대금에 따른 보수적 슬리피지 가정을 추가한다.
- 시장별 단순 보유, SMA 추세, 단순 모멘텀을 기준선으로 비교한다.
- 현재 후보군만 사용하는 검증 결과에는 생존편향 경고를 표시한다.

#### 1-3. 필수 평가 지표

- 비용 차감 CAGR 및 누적수익률
- 벤치마크 대비 초과수익
- Sharpe, Sortino, Calmar
- 최대낙폭과 회복기간
- 적중률, 평균 이익, 평균 손실, 기대값, profit factor
- turnover와 추천 빈도
- 시장·액션·기간·국면별 표본 수
- 최악의 월/분기 및 하위 10% 결과

완료 기준:

- 동일 설정과 데이터로 결과를 재현할 수 있다.
- 비용 전·후 결과와 벤치마크가 함께 표시된다.
- 평가 구간을 변경해도 핵심 결과가 급격히 붕괴하지 않는다.
- 운영 전략으로 승격할 최소 표본과 위험 한도가 문서화된다.

### Phase 2. 직교 신호 확장

목표: 기존 지표와 중복되지 않고 외부 평가 구간에서 가치가 확인된 신호만 추가한다.

구현 상태(2026-07-12): **연구 진단 기반 구현 및 로컬 검증 완료, 운영 모델 미반영**

- 추세, 다중 기간 모멘텀, 거래량·유동성, 위험·국면, 시장 상대강도 후보 신호를
  과거 시점 정보만 사용하는 별도 연구 계산 경로로 추가했다.
- 기존 기술점수 및 후보 신호 간 Spearman 상관, 상·하위 분위 순수익 차이, 기존 점수와
  결합한 증분 기대값·적중률·turnover proxy를 평가한다.
- 시장·국면·워크포워드 fold별 방향 일관성을 함께 표시하며 최소 표본과 중복 기준을
  충족하지 못한 신호는 제외한다.
- 검토 후보 기준은 비중복 평가일 30개, 워크포워드 fold 3개, 시장별 표본 20개,
  비용 차감 증분 기대값 양수, turnover 및 최대낙폭 비악화를 모두 요구한다.
- 연구 계산 또는 평가가 실패해도 운영 백테스트는 계속되며 진단만 `unavailable`로 표시한다.
- 모든 결과는 연구 전용이며 `adoption_permitted=false`로 반환한다. 현재 운영 점수
  30/25/15/15/15, 액션, 리포트 스키마, 저장 데이터에는 영향을 주지 않는다.

우선 검토할 신호군:

| 신호군 | 후보 기능 |
|---|---|
| 추세 강도 | SMA 기울기, ADX/DMI, 돌파 지속 기간 |
| 다중 기간 모멘텀 | 5/20/60/120일 수익률, ROC, 모멘텀 일관성 |
| 거래량·유동성 | 상대 거래량, OBV/CMF, 평균 거래대금, 거래대금 급감 |
| 위험·국면 | 실현변동성, ATR 백분위, 낙폭, 시장 변동성 국면 |
| 상대강도 | 종목 대 시장·섹터 상대수익과 상대 모멘텀 |
| 펀더멘털·이벤트 | yfinance 범위 내 밸류에이션, 품질, 실적·배당 일정 |

채택 절차:

1. 신호 정의와 경제적 가설을 먼저 작성한다.
2. 기존 신호와 상관관계 및 중복도를 측정한다.
3. 단독 성과와 기존 모델에 추가했을 때의 증분 성과를 비교한다.
4. 워크포워드 외부 구간과 여러 시장 국면에서 검증한다.
5. 비용 차감 기대값, 최대낙폭, turnover가 개선된 경우에만 채택한다.
6. 개선이 없는 신호는 코드와 운영 모델에서 제외한다.

점수 체계 변경은 `AGENTS.md`의 30/25/15/15/15 배점 변경 승인을 받은 후 진행한다.

### Phase 3. 뉴스 파이프라인 복구 및 품질 강화

목표: 뉴스가 실제로 수집되고, 어떤 뉴스가 어떤 판단에 사용됐는지 확인할 수 있게 한다.

구현 상태(2026-07-12): **코드·로컬 검증 및 Oracle 연결 측정 완료, 개선 배포 대기**

- 시장 3회와 종목 3회의 쿼리 예산을 분리하고 보유 2개·우선 후보 1개를 먼저 조회한다.
- 연결/읽기 타임아웃, 제한 재시도, DNS·TLS·timeout·HTTP·parsing·network 분류와
  `partial`/`unavailable` 상태를 구현했다.
- 3일 범위와 종목명 관련성을 검사하고 canonical URL, 유사 제목, 동일 이벤트를 제거한다.
- 모든 기사에 `headline-only` 근거와 증거 ID를 부여하고 검색어·제목·도메인·URL·기사 시각·
  수집 시각·실패 상세·실제 인용 경로를 `report_inputs.news_context`에 저장한다.
- 제외된 기사도 중복·시각·관련성·컨텍스트 한도 사유와 함께 저장해 필터링 결과를 재구성한다.
- 뉴스 수치 기여는 아직 모델링하지 않아 0으로 기록하며 운영 신뢰도 숫자를 변경하지 않는다.
- Oracle VM의 DNS/TLS/outbound/응답시간 확인은 운영 환경에서 수동 실행해야 한다.
- 운영 측정 결과 DNS·인증서 검증은 정상이지만 TLS handshake가 약 8~10초 걸리고 연속 요청은
  HTTP 429가 발생했다. 기본 연결 제한을 15초, 쿼리 간격을 5.5초로 조정했다.

#### 3-1. 연결 복구

- Oracle VM에서 GDELT DNS, TLS, 응답시간을 단계별로 점검한다.
- 연결 및 읽기 타임아웃을 분리하고 제한된 재시도와 지수 백오프를 적용한다.
- 실패 유형을 DNS, TLS, timeout, HTTP, parsing으로 구분한다.
- 지속 실패 시 허용된 GitHub Actions에서 사전 수집하는 방안을 별도 설계 검토한다.

#### 3-2. 검색 구조 수정

- 시장 공통 주제와 종목별 주제에 쿼리 예산을 분리한다.
- 보유 종목과 높은 우선순위 후보를 먼저 검색한다.
- 동일 URL·유사 제목·동일 이벤트 중복을 제거한다.
- 오래된 기사와 종목명이 우연히 일치한 기사를 제외한다.

#### 3-3. 감사 가능한 입력

- 리포트 입력 스냅샷에 검색어, 제목, 도메인, URL, 수집시각을 저장한다.
- 기사 본문을 읽지 않은 경우 `headline-only`로 명시한다.
- AI가 사용한 뉴스에는 출처와 시각을 연결한다.
- 뉴스가 없으면 이를 명확히 표시하고 뉴스 기여도를 0으로 처리한다.

완료 기준:

- Oracle 운영 리포트에 실제 GDELT 기사 수가 기록된다.
- 종목별 뉴스 검색이 테스트로 확인된다.
- 저장된 입력만으로 리포트의 뉴스 근거를 재구성할 수 있다.
- 뉴스 실패가 기술분석 리포트 전체 실패로 이어지지 않는다.

### Phase 4. AI 역할 및 정량 사실 보호

목표: AI를 계산 엔진이 아니라 설명·반론·누락 탐지 계층으로 사용한다.

#### 4-1. 백엔드 소유 필드

다음 값은 AI 응답을 신뢰하지 않고 백엔드 계산값으로 확정한다.

- 포트폴리오 평가액과 수익률
- 현재가와 시장 데이터 날짜
- 원시 기술점수와 데이터 품질
- 기본 액션과 신뢰도
- ATR 기반 목표가와 손절가
- 포지션 크기 가이드의 계산값

AI는 다음 내용을 생성한다.

- 상승 논리와 하락 논리
- 주요 위험과 기회
- 데이터 사이의 모순
- 누락된 증거와 데이터 한계
- 추천 무효화 조건
- 뉴스의 관련성 설명

#### 4-2. 응답 의미 검증

- 입력에 없는 종목은 제거한다.
- stale/data-limited 종목은 WATCH, confidence 0 규칙을 강제한다.
- 목표·손절 관계와 허용 액션을 검증한다.
- AI가 백엔드 사실과 다른 내용을 작성하면 백엔드 값을 우선하고 차이를 로그로 남긴다.
- 필요하면 같은 OpenAI 모델로 초안 후 비판 검토를 수행하되 비용과 지연을 측정한다.

현재 `ReportContent` 스키마 변경이 필요한 경우에는 구현 전에 명시적 승인을 받는다.

완료 기준:

- AI가 잘못된 가격이나 액션을 반환해도 저장 결과는 백엔드 사실을 유지한다.
- 최신 리포트에서 입력·출력 종목 일치 여부를 자동 검사한다.
- AI 사용 여부와 fallback 사유가 UI 및 시스템 상태에서 확인된다.

### Phase 5. 포트폴리오 기대값과 위험 관리

목표: 개별 종목 점수가 아니라 포트폴리오 전체의 비용 차감 기대값과 하방 위험을 관리한다.

#### 5-1. 기대값 분리

- 예상 상승 폭, 예상 하락 폭, 성공확률, 거래비용을 분리한다.
- `expected value = p_up * upside - p_down * downside - costs` 형태로 비교한다.
- 기대수익 모델과 위험 모델을 별도로 평가한다.
- 확률은 충분한 외부 표본이 없으면 정량 확률처럼 표시하지 않는다.

#### 5-2. 포지션 크기 제약

현재 fixed-fractional 한도에 다음을 추가한다.

- 포트폴리오 손실 예산
- 종목 변동성과 갭 위험
- 시장 베타와 종목 간 상관관계
- 섹터·국가·통화 집중도
- 평균 거래대금과 유동성
- 기존 동일 팩터 노출

최종 금액 가이드는 위 제약 중 가장 보수적인 한도를 사용하며 주문 수량이나 주문 버튼은
제공하지 않는다.

완료 기준:

- 단일 종목 점수가 높아도 집중도·상관관계 때문에 금액이 제한된다.
- 추천마다 기대값 구성과 적용된 제약을 설명할 수 있다.
- 포트폴리오 최대낙폭과 집중 위험이 백테스트 결과에 포함된다.

### Phase 6. 그림자 운영과 승격 체계

목표: 개발 중인 신호가 운영 추천에 즉시 영향을 주지 않도록 한다.

- 기존 모델을 champion, 신규 모델을 challenger로 구분한다.
- challenger는 최소 8~12주 동안 그림자 운영한다.
- 평가 기간 중 파라미터를 변경하지 않는다.
- 변경 시 새 모델 버전을 만들고 평가 기간을 다시 시작한다.
- 백테스트와 실시간 성과의 편차를 감시한다.
- 모든 추천에 모델 버전, 설정, 지표, 뉴스 입력 스냅샷을 연결한다.

승격 조건 예시:

- 사전에 정한 최소 표본 수 충족
- 비용 차감 기대값이 양수
- 기준선보다 위험조정 성과가 개선
- 최대낙폭이 허용 한도 이내
- 특정 한 시장·한 국면에만 의존하지 않음
- 데이터 누락 및 운영 실패율이 허용 범위 이내

## 8. 최종 판단 기준

AlphaPilot의 개선 여부는 지표 수나 AI 응답의 복잡성이 아니라 다음으로 판단한다.

- 추천 결과를 시간 순서대로 재현할 수 있는가
- 비용 차감 후 벤치마크보다 나은 기대값이 있는가
- 최대낙폭과 집중 위험이 허용 범위 안에 있는가
- 여러 시장과 국면에서 성과가 유지되는가
- 뉴스와 AI의 근거를 사후 감사할 수 있는가
- 운영 실패 시 안전하게 기술 전용 리포트로 전환되는가

이 기준을 통과한 변경만 실제 추천 모델에 반영한다.

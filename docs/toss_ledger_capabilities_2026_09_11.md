# Toss 성과 원장 조회 범위 조사

검토일: 2026-09-11. [공식 OpenAPI](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)
버전 1.2.15 및 현재 저장소의 Toss 서비스·DB 마이그레이션을 대조했다.
개별 계좌 요청·토큰 발급·운영 DB 쓰기는 하지 않았다. 아래 지원 여부는 명세 기준이며
실제 계좌의 권한, 과거 자료 보존 기간, 응답 완전성을 검증했다는 뜻이 아니다.

## 조회 기능

| 필요한 자료 | 공식 경로/필드 | 판단 |
|---|---|---|
| 계좌 식별 | GET `/api/v1/accounts` | 현재 종합매매 계좌 대상. 원장 계좌별 범위 확정에 사용 |
| 현재 보유 | GET `/api/v1/holdings` | 국내·미국 주식 잔고 대조에 사용. 과거 거래 원장이 아님 |
| 주문·체결 누계 | GET `/api/v1/orders`, `/api/v1/orders/{orderId}` | 수량·평균 체결가·체결금액·수수료·세금·최종 체결시각·결제일 필드 존재 |
| 개별 체결별 내역 | `Order.execution`은 `OrderExecution` 객체 | 안정적인 개별 체결 ID와 체결 배열을 확인하지 못함. 체결 누계 관측으로 취급 |
| 실제 수수료·세금 | 주문의 `execution.commission`, `execution.tax` | null 가능. 현재 수수료율로 빈 과거 금액을 메우지 않음 |
| 현재 수수료율 | GET `/api/v1/commissions` | 비율과 적용 기간 정보. 실제 과거 부과 내역을 대체하지 못함 |
| 가용 현금 | GET `/api/v1/buying-power` | 매수 가능 금액. 예수금·출금 가능액·결제 원장 대체 금지 |
| 입출금·이체 내역 | 전용 경로 확인 못함 | 거래명세서 등 별도 증거 필요 |
| 계좌 배당·분배금 입금 | 전용 경로 확인 못함 | 세전액·원천징수·실입금 자료 필요. 종목 배당 일정으로 대체 불가 |
| 실제 환전 내역 | 전용 경로 확인 못함 | 양 통화 금액·실제 적용 환율·비용 증거 필요 |
| 참고 환율 | GET `/api/v1/exchange-rate` | `dateTime` 조회 가능. 실제 체결 환율과 다를 수 있음 |
| 거래 세션 | GET `/api/v1/market-calendar/KR`, `/US` | 기준일 조회 가능. 국내는 KRX+NXT 통합, 특수장 제외. 추가 달력 검증 후보 |

명세 전체 경로·관련 응답 스키마를 점검했다. 미확인은 영구적인 미지원 선언이 아니며,
새 명세나 공식 답변을 확보하면 재검토한다.

## 주문 수집에서 반드시 지킬 조건

1. OPEN과 CLOSED를 모두 수집한다. 취소됐거나 거부 관련 상태라고 체결량을 0으로
   추정하지 않는다. 같은 주문이 양쪽에 보이더라도 계좌+orderId 기준으로 묶는다.
2. CLOSED는 기본 20, 최대 100건의 커서 페이지 방식이다. OPEN에서는 limit/cursor가
   적용되지 않는다. 페이지 완주와 경제적 원장 완전성은 다른 검증 항목이다.
3. `from`/`to`는 KST 주문 생성일 범위다. 체결일 범위로 해석하면 장기 미체결 주문의
   늦은 체결을 놓친다. 알려진 진행 주문 상세를 재조회하고 기간 경계도 겹쳐 수집한다.
4. 날짜 미지정 조회가 가능하지만 실제 최장 보존 기간은 명세만으로 확정하지 못했다.
   최초 수집에서 관측 최과거일·계좌 개설/명세서 기간을 대조해야 한다.
5. API가 지원하지 않는 호가 유형의 주문은 목록과 상세 양쪽에서 빠질 수 있다.
   따라서 API 수집 완료만으로 전체 거래 내역이 완전하다고 표시하지 않는다.
6. 누적 체결수량·누적금액의 변화는 개별 체결 이벤트가 아니다. 누적값을 매번 새로운
   거래금액으로 더하지 않는다. 최종 체결시각에 전체 거래가 발생한 것으로 배치하지 않는다.
7. 정정·대체 주문 사이의 경제적 연결은 명세의 orderId만으로 확정하지 않는다. 중복
   의심·수량 불일치는 원문을 유지하고 대사 대상으로 남긴다.

토큰은 새로 발급하면 기존 토큰을 무효화하는 계약이다. 향후 조회 수집기를 만들 때 기존
보유 동기화와 토큰 발급을 조율해야 한다. 문서 조사만을 위해 운영 토큰을 교체하지 않았다.

## 현재 AlphaPilot과의 차이

- `assets`는 최신 보유 상태이며, Toss 동기화에서 종료 보유를 제거한다. 과거 거래를
  이 테이블로 복원하지 않는다. 원장 종목은 삭제 가능한 asset_id에 종속시키지 않는다.
- `portfolio_snapshots`는 보고서 시점의 평가액이며 현금흐름 전후 평가값이 아니다.
- Toss 현금 자산은 서비스의 안내대로 가용 매수금액이다. 이를 기초 예수금으로 옮겨
  새 원장의 정산잔액이라고 표시하지 않는다.
- `performance_logs`와 `recommendation_cycles`는 추천 관찰 데이터다. 실제 체결과의
  연결은 증거가 있을 때만 별도로 만들며 추천 신호 자체로 원장 이벤트를 만들지 않는다.

부분만 회계 계산에 반영한다. 첫 구현은 로컬 명세서/JSON의 검증과 원장 계산기로 한다.
